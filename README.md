# aram-augment-advisor
海克斯大乱斗强化符文助手

当前项目处于本地数据基础阶段：客户端先从本地激活版本读取数据，暂不依赖服务器、用户上传或自动联网更新。

## 当前开发方式

```bash
npm install
npm test
npm start
```

生成当前系统的可运行目录：

```bash
npm run dist:dir
```

Windows 安装包在 Windows 环境执行：

```bash
npm run dist:win
```

构建会把本地 `data/runtime/` 作为安装包资源带入。程序内的“手动同步全球数据”按钮会把更新后的版本保存到用户数据目录，并优先使用用户目录缓存。

当前内置的是用于验证链路的示例数据，不代表正式全球统计数据。

手动获取当前全球数据并保存到本地缓存：

```bash
npm run data:sync
```

同步脚本会读取数据源 manifest，限并发下载并校验 222 个数据文件，默认保存到被 Git 忽略的 `data/runtime/`。应用检测到本地缓存后优先使用缓存；同步失败时继续使用上一次成功激活的版本。

手动导入一个经过校验的数据版本：

```bash
npm run data:import -- /path/to/data-version
```

数据包必须包含 `manifest.json`，并在 `manifest.files` 中声明文件路径和 SHA-256。导入会先完成完整性校验，成功后才切换 `data/current.json`；失败时继续使用旧版本。

当前手动同步源是 `data.dtodo.cn` 的全球客户端数据接口。它用于验证本地数据链路，正式发布前仍需要单独确认统计字段、样本口径和来源稳定性。

出装优先读取英雄详情的 `build.fullItems`，或匹配 `build.coreItems` 与 `build.itemExtensions` 中对应核心的同组合统计，展示六件装（含鞋）；缺少六件统计时展示五件或更少，并标出数据不足。卡片列出的是装备组合，不表示购买顺序。

装备 ID 集合相同的记录只展示一次，保留样本量最多的一条，不累加可能重叠的样本。方案按样本量排序，胜率使用该套装备对应的 `wins / games`，不会把三件套胜率用于五六件装，也不会截断七件套或用单件统计补齐装备。成装样本不能与英雄整体胜率直接比较。目前仍是英雄基础出装参考，尚未根据已选海克斯调整。

## 计划中的功能

- LCU 读取选人阶段的当前英雄；
- 本地全球统计查询；
- 当前英雄与海克斯的条件胜率；
- 已选海克斯与候选海克斯的组合推荐；
- 游戏内只读 OCR 浮窗；
- Windows 打包和手动数据更新。

当前 LCU 接入是只读的：程序通过 League Client lockfile 连接本地 LCU，读取游戏阶段和选人 session，在检测到 `ChampSelect` 时自动选择当前英雄。它不会自动选英雄、锁定英雄、交换 bench 或写入选人操作。
