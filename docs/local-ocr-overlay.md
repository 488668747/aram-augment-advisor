# 游戏内本地 OCR 与顶部三卡浮窗

本功能只读取 LCU、所选屏幕的三个标题区域和本地统计数据。它不会上传截图或战绩、不会操作游戏选项；装备推荐仍在主应用中查看。

## 使用

1. 启动助手和国服客户端。应用会读取选人阶段当前英雄；进入实际对局后，再通过 LCU 对局数据核实最终英雄。
2. 游戏优先使用无边框窗口或窗口模式。在应用的“本地 OCR”区域选择游戏所在显示器，开启自动识别。
3. 打开海克斯选择界面。标准 16:9 布局可以先用默认区域；若无法识别，点击截图校准，助手会短暂隐藏后截取所选屏幕。
4. 只框选左、中、右三张卡片的**名称文字**，不要包含下面的标签、说明或卡片竖边框。保存后配置只存在本机用户目录。校准期间自动识别暂停，取消或保存后恢复。
5. 三个名称识别后，屏幕顶部出现按左、中、右排列的浮窗。窗口不抢游戏焦点并透传鼠标点击。识别到名称但没有当前英雄统计时显示未知胜率，不使用全局胜率替代。
6. 可以在主应用中手动识别，或按 F8 触发一次；关闭开关、退出实际对局或客户端断开时隐藏浮窗。

首次打开浮窗需要完整识别三张不同卡片。已有结果时，短暂漏读保留布局，两张可读时未读位置留空；连续漏读则清空结果。任何阶段变化都会废弃尚未完成的旧识别任务，不把上一局结果带入新对局。

只在 `InProgress` 且能核实本局英雄时自动截图；选人、加载、大厅和结算阶段不会自动截图。校准截图是用户主动操作，可在主应用使用，但请让游戏画面位于助手后面。

## 数据含义与限制

浮窗使用“当前英雄＋该海克斯”的本地样本胜率与场次，既不是本局必胜概率，也不是根据已选海克斯计算的联动胜率。截图保留在内存，用完即释放；不保存整屏截图到磁盘。三框校准的坐标、显示器与开关保存在用户目录的 `overlay-settings.json`。

不同分辨率、游戏 UI 缩放、特殊卡片布局和字体可能需要重新校准。独占全屏、多个显示器不同缩放比例，以及真实国服客户端仍需 Windows 实机验证；识别有疑问时保持未知，最终选择由玩家操作。

macOS 预览截图需要系统的屏幕录制权限。Windows 安装包自带 OCR 运行库和模型，不要求使用者安装 Python 或联网下载模型。统计 JSON 已内置，图标仍走 CDN。

## 开发与验证

```bash
npm ci
npm run ocr:prepare
npm test
npm start
npm run dist:win -- --publish never
```

OCR 依赖 Tesseract.js 和离线中英文 traineddata，来源、许可和 SHA-256 记录位于 `resources/ocr/NOTICE.md` 与 `models.json`。不复制 ARAMGG 的源码、图片或 OCR 模型。
