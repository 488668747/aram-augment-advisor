# 本地 OCR 与顶部三卡浮窗实施计划

> **For Claude:** 按本计划逐项实现并进行行为验证，复用当前独立工作树。

**Goal:** 在实际对局中本地识别左中右三张海克斯，以不抢焦点的顶部透明浮窗展示当前英雄对应统计。

**Architecture:** LCU 只读快照保留本局英雄；独立控制器按阶段开启单串行截图/OCR，阶段变化使旧识别结果失效。OCR 使用公开许可的本地中文/英文识别资源，数据读取沿用当前本地查询。屏幕与三个标题区域可在主应用中校准并保存到用户目录。

**Tech Stack:** Electron、Node.js、Tesseract.js 本地 WASM OCR，保持现有界面与数据结构。

## 验收与实现顺序

1. OCR 引擎与离线资源：确认许可，添加 Node 可运行的本地 OCR，确保运行时不下载模型；用独立生成的中文卡片标题图做识别检查。
2. 名称匹配与控制器：名称规范化、按槽位匹配本地名称、未知保留空位、英雄条件统计；只在 InProgress、已知英雄、启用时运行。先写并运行失败测试，再实现；测试退出阶段后丢弃旧异步结果、不并发识别和清空浮窗。
3. LCU 生命周期：从 ChampSelect 保留本局英雄到 InProgress，离开游戏清空。补充阶段序列测试。
4. Electron 集成：选择显示器、截取校准区域、配置落盘、顶部透明不抢焦点且点击穿透的三卡窗口；仅固定本地窗口可用 IPC。
5. 主应用增加开关、状态、手动识别和本地截图三框校准；浮窗只展示海克斯名称/稀有度/当前英雄胜率/场次，不展示装备或伪造组合胜率。
6. 验证：单元测试，真实本地 OCR 图片，模拟 HTTPS LCU 端到端到浮窗，阶段退出/断开关闭浮窗；Windows x64 打包并核实模型/worker/运行依赖在包内。真实 Windows 游戏截图与多分辨率需用户后续实测。

## 边界

不复制 aramgg_client 源码或图片，不接上传或服务端，不增加自动选取，不把推荐分当胜率。当前仍为英雄＋单海克斯统计，已选海克斯的组合统计另行实现。Windows 测试包与代码均使用中文语义提交。

## 实施结果

- 使用 Tesseract.js 6.0.1 与 SHA-256 固定的本地中英文模型，无新增 Python/外部语言环境。
- 识别不确定时采用有限次图像缩放重试，仅文字重复一致时选取原始结果，不虚增置信度。
- 通过 LCU gameflow session 与当前召唤师身份核实对局最终英雄，拒绝阶段冲突或身份不一致；服务内部合并并发查询。
- 独立审查发现的旧英雄缓存、IPC 初始化、校准失败暂停问题已修正并复核。
- `npm test`：50 项通过；`npm run verify:overlay`：真实本地中文字图、三槽位、英雄统计、阶段清空与窗口权限通过。
- 真实 Electron 校准保存与截图/落盘失败暂停验证通过。
- Windows x64 0.2.0 安装包构建与归档完整性通过；统计数据、模型、worker/WASM 文件校验通过，并从 Windows 包资源在 macOS Electron 中成功加载 OCR。
- Windows 真机游戏、不同分辨率/缩放和独占全屏仍待使用者实测。
